# iTu — 截图工具

Windows 桌面截图工具，复刻 QQ 截图与 Windows 11 截图工具的核心交互。
工程目录与产物都叫 `iTu`（`iTu.exe`）。

**框架依赖版单文件 435KB，零第三方运行时依赖**（OCR 走系统自带 PowerShell + WinRT）。

---

## 快速开始

### 下载即用的两个版本

| 版本 | 目录 | 体积 | 说明 |
|---|---|---|---|
| **独立版**（推荐） | `dist/iTu-standalone/` | 49 MB | 内含 .NET 运行时，**任何 Windows 10/11 机器双击即用**，无需安装任何东西 |
| 轻量版 | `dist/iTu/` | 435 KB | 需要系统已安装 .NET 10 Desktop Runtime |

两个目录里都只有 `iTu.exe` 一个文件——OCR 脚本已作为资源内嵌进 exe，运行时用
`-EncodedCommand` 从内存执行，无需再附带 `ocr.ps1`。

> 若双击后没有反应，多半是用了轻量版但系统没装 .NET 10 Desktop Runtime
> （显示"需要安装 .NET"或直接闪退）。改用独立版即可。

### 从源码构建

```bash
# 构建
dotnet build -c Release

# 发布轻量版（需系统已装 .NET 10 Desktop Runtime）
dotnet publish -c Release -r win-x64 -p:SelfContained=false \
  -p:PublishSingleFile=true -p:DebugType=none -o dist/iTu

# 发布独立版（零依赖）
dotnet publish -c Release -r win-x64 -p:SelfContained=true \
  -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true \
  -p:DebugType=none -o dist/iTu-standalone
```

> 注意：`--self-contained false` 在命令行里容易被上一次发布的 RID 状态干扰，
> 必须写成显式属性 `-p:SelfContained=false` 才能得到小体积的框架依赖包。

#### 一键发布（推荐）

双击或命令行运行 `iTu\publish.cmd` 即可，它按顺序做六件事：

1. 检查是否有 iTu 正在托盘运行——**运行中的 exe 不能被覆盖**，检测到就中止并提示先退出；
   加 `--force` 则先结束进程再继续（会中断正在进行的截图/录制）
2. 清掉旧 `dist`
3. 发布轻量版 → `dist/iTu/`
4. 发布独立版 → `dist/iTu-standalone/`
5. 构建桌面快捷方式工具 `desktoplink`
6. 把桌面上的 `iTu` 快捷方式刷新到本次构建

桌面图标固定指向 `dist/iTu-standalone/iTu.exe`，所以**每次发布覆盖同名文件后，
桌面那个图标双击就是当前构建**，不需要重新创建；脚本第 6 步只是同步版本备注
并顺带刷新图标缓存。图标用的是 `iTu.exe` 的内嵌资源（`app.ico`），换版本不用改。

> 桌面快捷方式由 `desktoplink/` 这个独立小工具生成（`IShellLink` / `IPersistFile` 接口）。
> 没有用脚本宿主去 `CreateObject` 创建，是因为本机安全策略会拦这类 COM 实例化。
> 工具会把自己写出的 `.lnk` 立刻读回来比对目标、起始目录、图标，打印 `[PASS]` 才算成功。

### 启动后

程序常驻托盘，启动时只弹一条托盘气泡（显示当前快捷键），**不弹任何置顶面板**——
旧版的 340×232 启动提示面板会在按快捷键截图时被一起拍进画面（就是"右上角多余的窗口"），已移除。

再次双击 `iTu.exe` 会唤起已运行的实例直接开始截图（不会启动第二份）。

桌面上的 `iTu` 图标指向 `dist/iTu-standalone/iTu.exe`（独立版，双击即用）。
若双击后托盘里还是旧版本，说明旧实例还在跑——先右键托盘退出，再双击桌面图标。

### 排查

- 启动日志：`%TEMP%\itu-<用户名哈希>.log`（托盘「关于 / 诊断」里显示完整路径）
- 托盘右键 →「关于 / 诊断」：版本、PID、程序路径、热键注册状态、日志路径
- 托盘右键 →「打开日志文件」：用记事本打开日志

## 关键实现说明

### 单图层遮罩（分层窗口）

普通子控件的"透明"是由父窗体垫底的，圆角抗锯齿像素会和透明键色混合，出现粉边/锯齿。
因此遮罩层用 `WS_EX_LAYERED` + `UpdateLayeredWindow` 提交预乘 alpha 的 32 位 DIB，
由 DWM 按像素 alpha 合成；所有控件（胶囊、次级胶囊、弹层、提示条）都画进**同一张位图**，
命中测试也在这张位图对应的坐标系里做，所以不存在"控件窗口抢焦点 / 层级错乱"的问题。

- 高频重绘用可复用的 `SurfaceBuffer`：只在尺寸变化时重建 DIB/DC，避免每次提交都创建 GDI 对象。
- 屏幕坐标 → 浮层客户区统一走 `PixelOrigin`；→ 最终图片统一减 `Selection.Left/Top`。

### 混合 DPI 下的像素对齐

Windows 缩放会让逻辑坐标与物理像素脱节，导致选区错位。方案：

1. 进程声明 `PerMonitorV2`（`ApplicationHighDpiMode`）
2. 虚拟桌面拼成一张浮层，用 `SetWindowPos` 按**物理像素**定位
3. 鼠标坐标一律取 `GetCursorPos()`（物理像素），不经过 WinForms 缩放
4. 浮层忽略 `WM_DPICHANGED` 的尺寸建议

### 次级胶囊：宽度按内容算，滑杆自成一段

次级胶囊原来固定取主胶囊宽度的一半（595/2≈297）。"形状"这层的内容是
3 个工具格 + 描边/填充 + "粗细"标签 + 滑杆 + 数值 + 色块，实测需要 ~370px，
于是滑杆被挤成 40px、数值被画到色块上。现在：

- `ToolFlyout.MeasureWidth()` 按元素实际尺寸累加出最小宽度，调用方取
  `max(主胶囊一半, 该值)` 再按虚拟桌面夹取。
- 标签、滑杆、数值各有独立的矩形（`_labelRect / _sliderRect / _valueRect`），
  绘制不再"从滑杆位置反推文字坐标"。
- 圆头圆心只在两端各内缩一个半径的区间内移动，拖到最右也不会顶出胶囊。

滑杆的拖动还有一处必踩的坑：拖的时候指针几乎必然滑出胶囊（它只有一行高）。
`OverlaySession` 原来只把飞层**矩形内**的移动转发给 `ToolFlyout`，一出界就断流，
值停在中途，事件还会继续往下走变成别的操作。现在只要 `DraggingSlider` 为真就继续转发。

### 模态取色框必须切断全局鼠标输入

输入主通道是低级鼠标钩子（`WH_MOUSE_LL`），它只看坐标、不看点击落在哪个窗口。
系统取色框虽然是模态窗口，但它上面的每次点击照样会被钩子送进选区状态机：

- 点在选区外 → 开始重新框选；抬手时新选区不足 3px → 取"鼠标下的窗口"并 `Finish()`，
  整次截图直接结束。真机复现：选区从 700×140 变成 1263×1056，会话终结。
- 点在选区内 → 变成画一笔标注。

也不能在钩子回调里直接 `ShowDialog`：那会开一个嵌套消息泵，钩子在同一线程重入。

现在的处理：

1. 点「自定义…」时先置 `_modalOpen`，三个指针入口与轮询通道一起早退；
2. 用 `owner.BeginInvoke` 把弹窗投递到浮层消息队列，本轮回调彻底返回后才 `ShowDialog`；
3. 关闭后重置光标基准与"上次按下"时间戳，避免残留事件被当成新的拖拽起点。

取色弹层本身还有两处定位问题：

1. **宽度/高度**：早期单行固定 326px 宽、38px 高。选区靠右时整块顶出屏幕
   （现象是"点了色块什么都没弹出来"）；主胶囊被压窄时它又比旁边的次级胶囊高一截。
   现在卡片高度直接取**次级胶囊的真实高度**（`capsuleH = _fly.Bounds.Height`），
   色块大小随之缩放，两者拼在一起是一条等高的行。
2. **落位顺序**：右侧同一行 → 左侧同一行 → 次级胶囊下方一条 → 上方一条 → 最后按屏幕夹取。
   每个候选都先夹回屏幕内再判定，所以"贴边但夹得回来"的位置不会被误判成放不下；
   判定时同时排除主胶囊与次级胶囊的矩形，永远叠不到前两级身上。
   卡片**只有一条**：7 个色块 + 「自定义…」在一行里排开，高度取次级胶囊高度。

弹层还要能自己收起来：点弹层以外的任何地方（另一个工具、主胶囊、选区、空白处）
都会先 `DismissPopup()` 再继续分发，所以"弹着色板去换工具"不会留下一个孤零零的色板；
点在色块上则是收起（再次点色块才重新弹出，不会关了又开）。

### 识图/翻译在截图界面里完成

这两个格位以前是"先结束会话 → 出图 → 弹面板，再识别/翻译"，两个后果：

- 截图里**没有文字**时，会弹出一个写着「未识别到文字」的空面板；
- 「翻译」永远只是把译文塞进面板，图上一个字都没变。

现在 OCR 在会话内跑（后台 `Task` + `BeginInvoke` 回投），**两个格位走同一条写回路径**，
不再有任何结果窗口（以前那个窗没有 owner、`Manual` 又没设坐标，直接落在屏幕左上角）：

| 结局 | 界面表现 |
|---|---|
| 没识别到文字 | 不弹任何窗口；「文字提取」/「翻译」格位旁贴一条「未识别到文字」，会话继续 |
| 识图成功 | 每行生成一条 `TranslationAnnotation`：用 `TextBackdrop` 采样背景色擦掉原文、按原图字号重写识别结果；同时把整段文字复制到剪贴板；格位旁贴「已提取 N 行 · 已复制」，照常保存/钉/分享 |
| 翻译成功 | 同一条路径，写入的是译文；格位旁贴「已翻译 N 行」，会话不结束 |

### 译文/识别结果的字号要和原图一致

旧实现按 `行框高度 × 0.72` 定字号，中英文混排必然错位（同一字号下中文墨迹更高，
套同一个系数会一大一小；反过来按墨迹高度直接当字号又会整体偏大）。现在**两次校准**：

1. `TextBackdrop` 逐行判墨迹，量出原文的**墨迹高度** `InkHeight`；
2. 把**原文本身**按 48px 渲染一次，量出它自己的"墨迹/字号"占比，
   用 `InkHeight ÷ 占比` 反推原图字号 —— 与字体、文种都无关。

该字号排不下时先**把铺底往右扩**（最多 2.2 倍宽，渐变延续右端色），
仍放不下才压缩字号，最后才收省略号。测量必须用与 `DrawString` 同一套 `StringFormat`
（`GenericTypographic` 量出来比实际排版窄 1~3%，卡边界时会把明明放得下的句子截成「…」）。

译文是**标注**，所以预览与出图共用同一条合成路径（`OverlayInk.Draw` / `Composite`），
保存落盘的那张图就是屏幕上看到的翻译结果。翻译服务静默回退原文（译文与原文逐行相同）
时判定为失败，只在格位旁提示，不把原文重画一遍冒充译文。

### 圆角条不能压住选区（截图贴顶、贴左下角时尤其明显）

`LayoutChrome` 里圆角条的原逻辑是"放上方，放不下就放到 `Selection.Top + 10`"，
于是选区贴屏幕顶边时，这条胶囊正好盖在待识别的那一行文字上 ——
既看不清也点不中。现在按**硬约束 + 打分兜底**排布：

| 候选（按顺序试） | 适用场景 |
|---|---|
| 选区上方（左/中/右对齐） | **只在选区上沿离屏幕顶还有一整条高度 + 24px 时**才作候选 |
| 选区左右空白区 | 贴顶 / 左上 / 右上截图；先试与胶囊竖直居中，再试与选区顶对齐 |
| 胶囊下方一条 | 左右都放不下（选区几乎占满宽度） |
| 屏幕四角空白带 | 选区铺在某一角时，对角那片一定是空的 |
| 重叠最小兜底 | 选区铺满整屏；按"压住选区/胶囊/功能条的面积"打分取最优，写日志 `策略=…/clamp` |

约束同时成立：**不压选区、不压主胶囊、不进功能条驻地**（功能条铺开时）。日志里
`[chrome] 选区=… 胶囊=… 圆角条=… 策略=above-left|left-pill|right-pill|pill-below|screen-tl|…`
就是这套排布的结果，真机脚本直接拿它做几何断言。

> 旧版只有 above/left/right/below 四个位置，四条全被挡时直接 `Clamp(above)`，
> 于是**截左下角的图时圆角条会被夹到屏幕左上角去**（用户报的问题）。
> 现在补了"与胶囊竖直居中""屏幕四角空白带"等候选，并且兜底改成"重叠面积最小"。

### 顶部功能条画在位图里，而不是另开一个窗口

图二那条「截图 / 录屏 / 长截图 / ○ 隐藏当前窗口」如果做成独立窗口，就会和过去一样在
截图里留下一条自己的影子（`Toast`/`HintTip`/启动面板都栽在这上面）。所以它和胶囊一样，
是同一张分层位图上的一个手绘对象（`Ui/QuickBar.cs`），命中由 `OverlaySession` 统一分发：

| 交互 | 行为 |
|---|---|
| 按住左侧六点手柄 | 整条跟着鼠标走，位置可留在任意地方（拖动中光标变 `SizeAll`） |
| 「截图」 | 弹出下拉菜单：自由截图 / 窗口截图 / **全屏截图**（全屏 = 选区取整块虚拟桌面，直接出图） |
| 「录屏」 | 置 `RecordRequested` 并结束本次会话，由 `AppContext` 接着开录制流程 |
| 「长截图」 | 明确回一条"未实现"，不假装成功 |
| 「○ 隐藏当前窗口」 | 圆圈是**选择框**：点圆圈把功能条收成一个小柄（点小柄恢复）；点文字不触发，拖文字等于拖整条 |
| 框选 / 拉伸选区 | 条自动隐藏（别挡画面） |
| 脏区框出来之后 | 保持隐藏（截图界面进入出图阶段，条不该再露脸）；`Finish()` 还会立刻重画它那块区域，屏幕上连一帧残影都没有 |

会话结束（含异常退出）一律 `RestoreHiddenWindows()`，不会让用户莫名其妙少一个窗口。



### 控制点与勾选框

2px 边框、八处控制点（四角 + 四边中点）是 **8px 圆圈 + 1.1px 描边**，命中半径 9px
（比视觉尺寸大一截，所以点起来不会觉得"这几个小圈很难抓"）。
中间四个控制点**两侧的扩拉线已取消** —— 那两根白色短线看着像控制点长毛了，
需要拉边直接拖边中点的圆圈即可。

圆角条上的「阴影」勾选框是 **15px 圆角方框（圆角 4px）** + 1.2px 冷灰描边、右距 20px，
勾选后整块填主色 + 三笔白勾。

### 胶囊尺寸是固定的

主胶囊 595×38、次级胶囊 300×38、颜色弹层高 38、圆角条 380×34、顶部功能条 46 高，
**全部不随截图大小缩放**。旧版按 `min(595, 选区宽-28)` 算宽度、图标与格位中心按比例缩，
窄选区时整条胶囊会缩成一小截、字也跟着变小，点击坐标还得跟着换算 —— 现在一律用基准尺寸，
只在超出屏幕时夹取。

### 共享字体不要 Dispose

`Theme.UiFont / SmallFont / MonoFont` 是全局共享的 `Font` 实例。
一旦被 `using` 释放，后续 `Graphics.DrawString` 会抛 `ArgumentException: Parameter is not valid`，
表现是"截图界面出过一次提示后整体不再刷新"。绘制方一律按只读引用使用。

### 自研 GIF 编码器

`System.Drawing.Common` 在 .NET 10 已无动画 GIF 写入能力
（无 `Encoder.TimeDelay`、无多帧 `SaveAdd`），因此实现了完整的 GIF89a 编码器：

- **中位切分量化**：5bit/通道直方图 → 32768 桶 → 中位切分成 256 色
- **LZW 压缩**：与 GIF 解码器严格对称——新字典条目为
  `old + first_char(current)`，键为 `(prev << 8) | firstChar[prefix]`
- 已用 Pillow 权威解码器回归验证，6 帧全部正确还原

### 录制：独立采集线程

抓帧不用 WinForms Timer，而是专用线程按固定节拍采样。录制面板要在录制过程中
被"暂停/停止/取消"，这些操作来自另一条线程；UI 定时器跨线程停不安全，
独立线程也让界面卡顿不再丢帧。

- 暂停只停止采样，`Elapsed` 扣除暂停区间，面板上的计时就是实际录制时长。
- 停止/取消都在后台线程执行（编码可能几秒），面板先切到"正在保存…"并拒绝关闭，
  避免 recorder 在编码途中被 Dispose；取消会删掉 ffmpeg 留下的半成品文件。
- 写管道队列在停止时**先排空再退出**，尾帧不会丢；超时丢弃会写日志。
- ffmpeg 产出按文件字节数校验，0 字节视为失败并清理，不会"提示已保存却给出空文件"。
- 面板优先放在选区外（下→上→右→左），避免自己被录进画面；四个方向都放不下时
  才允许压住画面，且可以拖动移开。

### OCR 后端选型

直接引用 `net10.0-windows10.0.19041.0` 会自动引入
`Microsoft.Windows.SDK.NET.dll`（约 25MB 的 WinRT 投影）。
改用 `net10.0-windows` + 系统自带 PowerShell 调用 WinRT 后，
单文件体积从 132MB（自包含）/ 25MB（框架依赖）降到 **435KB**。

## 已知限制

- OCR 依赖系统 PowerShell 5.1 与「光学字符识别」语言包；
  未安装时识图会明确报错而非静默失败
- 翻译依赖公网接口，无网络时只在「翻译」格位旁提示失败，不会把原文冒充成译文
- MP4 录制需要系统安装 ffmpeg；未安装时自动回退到内置 GIF，面板上会直接写明当前编码后端
- 全局热键被其它程序占用时会注册失败，托盘提示与「关于 / 诊断」里都会标出
